Webアプリケーション公開実践マニュアル（AWS EC2編）

手元のパソコンで作ったWebアプリケーション（Django / Flask / Servlet）を、クラウドサーバー（AWS EC2）に設置して、世界中のインターネットからアクセスできるようにするまでの全手順をわかりやすく解説します。

📋 目次ナビゲーション:
全体の仕組み ステップ1: EC2サーバーの作成 ステップ2: サーバーへのログイン ステップ3: ソフトウェアの準備 ステップ4: アプリの起動 ステップ5: Nginx受付係の設定 ステップ6: ブラウザ表示確認 困ったときは

全体の流れ（何をするのか？）

普段使っているパソコンの電源を切ると、その中で動いているアプリも外から見られなくなってしまいます。
そこで、24時間365日ずっとインターネットに繋がり続けている専用コンピューター（AWS EC2サーバー） を1台借りて、そこにプログラムを設置します。

構成の全体イメージ：
① あなたのPC（GitHubへコード送信） ➡ ② クラウド上のEC2サーバー（GitHubからダウンロード） ➡ ③ Nginx（受付係が80番ポートでアクセスを受け取る） ➡ ④ 各アプリ（Django:8000 / Flask:5000 / Servlet:8080）へ自動振り分け

1 ステップ 1: AWSでサーバー（EC2）を作ろう

AWSマネジメントコンソールから、Linux（Ubuntu）が入った仮想コンピューターを1台立ち上げます。

1-1. AWSにログインして東京リージョンを確認する

  1. ブラウザでAWSマネジメントコンソールにサインインします。
  2. 画面右上の地域が「東京（ap-northeast-1）」になっていることを確認します。
  3. 上部の検索バーに EC2 と入力し、一覧の「EC2」をクリックします。
  4. 左側メニューの「インスタンス」を開き、オレンジ色の「インスタンスを起動」ボタンをクリックします。

1-2. サーバーの基本設定

項目名選ぶ値理由・解説
名前とタグmy-web-server など自由サーバーを識別するための名前です。
OSイメージ (AMI)Ubuntu
(Ubuntu Server 24.04 LTS)		世界中で一番広く使われている安定したサーバー用Linuxです。
インスタンスタイプt2.micro または t3.micro「無料利用枠の対象」と書かれたものを選びます。

1-3. キーペア（サーバーの鍵）を作る

サーバーに遠隔ログインするための「秘密鍵」を発行します。紛失すると二度とサーバーに入れなくなるため大切に保管してください。

  1. 「キーペア (ログイン)」項目で、右側の「新しいキーペアの作成」をクリックします。
  2. キーペア名に my-key など半角英数で入力します。
  3. キーペアのタイプは RSA、ファイル形式は .pem を選びます。
  4. 「キーペアを作成」を押すと、パソコンに my-key.pem がダウンロードされます。安全なフォルダに保存してください。

1-4. ネットワーク設定（ファイアウォール）

インターネットからサーバーへの通信の「通り道」を決めます。

  1. 「ネットワーク設定」の右上の「編集」をクリックします。
  2. 「セキュリティグループを作成」を選び、以下の3つのルールが揃っていることを確認します。
種類ポート番号ソース（接続元）役割
SSH22自分のIP または 0.0.0.0/0自分のパソコンから遠隔操作するための通り道
HTTP80任意の場所 (0.0.0.0/0)ブラウザでWebサイトを見るための通り道
HTTPS443任意の場所 (0.0.0.0/0)暗号化された安全なWeb通信のための通り道
注意: HTTP（80番ポート）が開いていないと、後からブラウザでアクセスしてもエラーになります。必ずチェックを入れましょう。

1-5. インスタンスの起動

画面右下のオレンジ色の「インスタンスを起動」ボタンをクリックします。約1〜2分でステータスが「実行中」になります。

2 ステップ 2: 自分のパソコンからサーバーにログインしよう

手元のPCの黒い画面（ターミナル / PowerShell）から、クラウド上のサーバーへ「SSH」接続します。

2-1. サーバーの「パブリック IPv4 アドレス」をコピー

EC2のインスタンス一覧画面で、作成したサーバーをクリックし、下部に表示される 「パブリック IPv4 アドレス」（例: 54.238.123.45）をコピーします。

2-2. ターミナルから接続する

手元のPCで PowerShell（Windows）または ターミナル（Mac）を開きます。

① 鍵（.pem）を保存したフォルダに移動します（例: ダウンロードフォルダの場合）：

PowerShell
cd C:\Users\admin\Downloads

② サーバーへログインします（※IPアドレスと鍵ファイル名はご自身のものに書き換えてください）：

SSH接続コマンド
ssh -i my-key.pem ubuntu@54.238.123.45

③ 初回のみ「接続を続けますか？ (yes/no)」と聞かれるので、キーボードで yes と打ち込んで Enter を押します。

画面の左側の表示が ubuntu@ip-172-31-xx-xx:~$ に変わればログイン大成功です！これ以降はすべてサーバーの中でコマンドを実行します。

3 ステップ 3: サーバーに必要な道具を入れよう

3-1. サーバーの中身を最新にアップデート

Bash
sudo apt update && sudo apt upgrade -y

3-2. ソフトウェアを一括インストール

Python、Java 17、Tomcat 10、PostgreSQL、Nginx、Gitをまとめて導入します。

Bash
sudo apt install -y python3-pip python3-venv openjdk-17-jdk tomcat10 postgresql postgresql-contrib nginx git

3-3. GitHubからプログラム一式をダウンロード

Bash
cd /var/www
sudo git clone https://github.com/th-kairi/91_SampleProgram.git exshop
sudo chown -R ubuntu:ubuntu /var/www/exshop

4 ステップ 4: アプリケーションを動かそう

動かしたいエディションの手順を実行してください。（3つ全部同時に動かすことも可能です）

コース A: Django版（ポート 8000）

① 仮想環境の作成とパッケージ導入：

Bash
cd /var/www/exshop/01_Django
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt gunicorn
python manage.py migrate
python manage.py collectstatic --noinput

② 24時間常駐サービスとして登録して起動：

Bash
sudo bash -c 'cat < /etc/systemd/system/django_exshop.service
[Unit]
Description=Gunicorn instance for Django exShop
After=network.target

[Service]
User=ubuntu
WorkingDirectory=/var/www/exshop/01_Django
Environment="PATH=/var/www/exshop/01_Django/venv/bin"
ExecStart=/var/www/exshop/01_Django/venv/bin/gunicorn --workers 3 --bind 127.0.0.1:8000 exShop.wsgi:application

[Install]
WantedBy=multi-user.target
EOF'

sudo systemctl daemon-reload
sudo systemctl enable --now django_exshop

コース B: Flask版（ポート 5000）

Bash
cd /var/www/exshop/02_Flask
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt gunicorn

sudo bash -c 'cat < /etc/systemd/system/flask_exshop.service
[Unit]
Description=Gunicorn instance for Flask exShop Nordic
After=network.target

[Service]
User=ubuntu
WorkingDirectory=/var/www/exshop/02_Flask
Environment="PATH=/var/www/exshop/02_Flask/venv/bin"
ExecStart=/var/www/exshop/02_Flask/venv/bin/gunicorn --workers 3 --bind 127.0.0.1:5000 run:app

[Install]
WantedBy=multi-user.target
EOF'

sudo systemctl daemon-reload
sudo systemctl enable --now flask_exshop

コース C: Servlet版（Tomcat 10 + PostgreSQL）

① PostgreSQLの初期化とデータ流し込み：

Bash
sudo -u postgres psql -c "CREATE USER exshop WITH PASSWORD 'exshop_pass';"
sudo -u postgres psql -c "CREATE DATABASE exshop_db OWNER exshop;"

cd /var/www/exshop/03_Servlet
PGPASSWORD='exshop_pass' psql -U exshop -d exshop_db -h localhost -f sql/schema.sql
PGPASSWORD='exshop_pass' psql -U exshop -d exshop_db -h localhost -f sql/data.sql

② WARファイルをTomcatに配置して再起動：

Bash
sudo cp /var/www/exshop/03_Servlet/target/exShop.war /var/lib/tomcat10/webapps/ROOT.war
sudo systemctl restart tomcat10

5 ステップ 5: 受付係（Nginx）を設定して公開しよう

外部からの80番ポートへのWebアクセスを受け取り、各アプリへ交通整理して案内する設定を行います。

Bash
sudo bash -c 'cat < /etc/nginx/sites-available/default
server {
    listen 80 default_server;
    server_name _;

    location /static/ {
        alias /var/www/exshop/01_Django/static/;
    }
    location /media/ {
        alias /var/www/exshop/01_Django/media/;
    }

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host \$host;
        proxy_set_header X-Real-IP \$remote_addr;
        proxy_set_header X-Forwarded-For \$proxy_add_x_forwarded_for;
    }

    location /flask/ {
        proxy_pass http://127.0.0.1:5000/;
        proxy_set_header Host \$host;
        proxy_set_header X-Real-IP \$remote_addr;
    }

    location /servlet/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_set_header Host \$host;
        proxy_set_header X-Real-IP \$remote_addr;
    }
}
EOF'

# テストと再起動
sudo nginx -t
sudo systemctl restart nginx

6 ステップ 6: ブラウザで実際に見てみよう！

おめでとうございます！これでインターネットへの本番公開が完了しました。

PCやスマートフォンのブラウザを開いて、以下のURLにアクセスしてください：

  • Django版（ストリート系デザイン）: http://<パブリックIP>/
  • Flask版（北欧ナチュラル系デザイン）: http://<パブリックIP>/flask/
  • Servlet版（ラグジュアリー・シック系デザイン）: http://<パブリックIP>/servlet/

困ったときのトラブルシューティング

Q1. ブラウザで開いても「応答時間が長すぎます」「接続できません」となる

➡ 原因: AWSのセキュリティグループで、HTTP（ポート80）が開いていません。
解決策: AWS管理画面の「EC2」➡「セキュリティグループ」➡「インバウンドルールを編集」で「HTTP / 80 / 0.0.0.0/0」を追加してください。

Q2. 「502 Bad Gateway」というエラー画面が出る

➡ 原因: Nginx（受付係）の奥で動くアプリ（DjangoやFlaskなど）が止まっています。
解決策: sudo systemctl status django_exshop を実行し、赤文字のエラーが出ていないか確認してください。

Q3. 画面は開くが、画像やCSSが崩れて文字だけになる

➡ 原因: 画像やCSSのアクセス権限または収集が不足しています。
解決策: sudo chown -R ubuntu:ubuntu /var/www/exshop を実行してください。
